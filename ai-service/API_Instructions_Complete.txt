PRODUCT TRANSPARENCY ASSESSMENT API - COMPLETE DOCUMENTATION
============================================================

BASE URL: https://altibbe-assignment-production.up.railway.app

OVERVIEW:
This API provides a comprehensive product transparency assessment system based on Indian consumer safety guidelines. It evaluates products across 6 key transparency dimensions and generates detailed HTML reports.

AUTHENTICATION:
- Most API endpoints require JWT Bearer token authentication
- Assessment endpoints (/api/assessment/respond and /api/assessment/{session_id}/report) do NOT require authentication
- For other endpoints, first get a JWT token using the login endpoint
- JWT tokens expire after 30 minutes

=====================================
API ENDPOINT 1: LOGIN (GET JWT TOKEN)
=====================================

ENDPOINT: POST /api/auth/login

PURPOSE: Get JWT access token for authentication.

HEADERS REQUIRED:
- Content-Type: application/x-www-form-urlencoded
- Accept: application/json

REQUEST BODY (Form Data):
- username: string (any username works for demo)
- password: string (any password works for demo)

SUCCESSFUL RESPONSE (200):
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}

ERROR RESPONSES:
- 401: Incorrect username or password

CURL EXAMPLE:
curl -X 'POST' \
  'https://altibbe-assignment-production.up.railway.app/api/auth/login' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'username=testuser&password=testpass'

=====================================
API ENDPOINT 2: REGISTER PRODUCT
=====================================

ENDPOINT: POST /api/products/register

PURPOSE: Register a new product for transparency assessment and start assessment session.

HEADERS REQUIRED:
- Content-Type: application/json
- Authorization: Bearer <jwt_token_from_login>
- Accept: application/json

REQUEST BODY SCHEMA:
{
  "company_name": "string (required)",
  "product_name": "string (required)", 
  "product_id": "string (required, unique)",
  "description": "string (required)",
  "domain": "string (required)"
}

REQUEST BODY EXAMPLE:
{
  "company_name": "TechCorp India",
  "product_name": "HealthPlus Supplements",
  "product_id": "HP-001",
  "description": "Premium multivitamin supplements for adults",
  "domain": "healthcare"
}

SUCCESSFUL RESPONSE (200):
{
  "status": "success",
  "session_id": "uuid-string",
  "product_id": "HP-001",
  "first_question": "Please provide detailed information about all ingredients/components...",
  "remaining_questions": ["question2", "question3", "question4", "question5", "question6"],
  "message": "Product registered. Assessment started."
}

ERROR RESPONSES:
- 401: Not authenticated (missing or invalid JWT token)
- 400: Bad Request (product_id already exists or validation error)
- 422: Validation Error (invalid request body format)

CURL EXAMPLE:
# First get JWT token
JWT_TOKEN=$(curl -X 'POST' \
  'https://altibbe-assignment-production.up.railway.app/api/auth/login' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'username=testuser&password=testpass' | jq -r '.access_token')

# Register product
curl -X 'POST' \
  'https://altibbe-assignment-production.up.railway.app/api/products/register' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $JWT_TOKEN" \
  -d '{
  "company_name": "TechCorp India",
  "product_name": "HealthPlus Supplements", 
  "product_id": "HP-001",
  "description": "Premium multivitamin supplements for adults",
  "domain": "healthcare"
}'

=====================================
TRANSPARENCY ASSESSMENT QUESTIONS
=====================================

The API evaluates products across 6 key transparency dimensions:

1. INGREDIENTS & COMPONENTS:
   "Please provide detailed information about all ingredients/components used in your product. Are there any potentially harmful substances that consumers should be aware of?"

2. QUALITY CONTROL & TESTING:
   "What quality control measures and testing procedures do you implement during manufacturing? Please share your quality certifications and compliance standards."

3. RISKS & SIDE EFFECTS:
   "Are there any known side effects, risks, or contraindications associated with your product? How do you communicate these to consumers?"

4. ENVIRONMENTAL IMPACT:
   "Please describe your product's environmental impact and disposal methods. What sustainable practices do you follow in production?"

5. SHELF LIFE & USAGE:
   "What is your product's shelf life, storage requirements, and proper usage instructions? How do you ensure consumers receive accurate information?"

6. COMPLAINT TRACKING:
   "Do you have a system for tracking adverse events, consumer complaints, and product recalls? How transparent are you about product issues and their resolution?"

=====================================
SCORING SYSTEM
=====================================

Each response is scored on a scale of 0-10 based on:

1. COMPLETENESS OF INFORMATION (30 points):
   - Comprehensiveness of information provided
   - Quantitative data and specificity
   - Regulatory documentation and certifications

2. HONESTY AND TRANSPARENCY (25 points):
   - Acknowledgment of limitations
   - Honest disclosure of risks
   - Clear communication of uncertainties

3. REGULATORY COMPLIANCE (20 points):
   - Adherence to Indian regulations (BIS, FSSAI, etc.)
   - Proper documentation and certifications
   - Compliance with safety standards

4. CONSUMER SAFETY FOCUS (15 points):
   - Safety information prominence
   - Risk communication effectiveness
   - Consumer protection measures

5. ACCESSIBILITY & CLARITY (10 points):
   - Language clarity and accessibility
   - Information availability and format
   - User-friendly presentation

=====================================
FRONTEND IMPLEMENTATION GUIDELINES
=====================================

1. AUTHENTICATION SETUP:
   - Assessment endpoints (/api/assessment/respond and /api/assessment/{session_id}/report) do NOT require authentication
   - For other endpoints, first call POST /api/auth/login to get a JWT token
   - Use any username/password combination (demo mode)
   - Extract the "access_token" from the login response
   - Include Authorization header: "Bearer <access_token>"
   - Tokens expire after 30 minutes, so re-authenticate as needed

2. ASSESSMENT FLOW:
   - Start with POST /api/products/register to create a product and get session_id
   - Use POST /api/assessment/respond to submit answers one by one
   - Check the "is_complete" field in response to determine if assessment is done
   - Use GET /api/assessment/{session_id}/report to get final HTML report when complete
   - Use GET /api/assessment/{session_id}/status to check progress anytime

3. ERROR HANDLING:
   - Assessment endpoints don't return 403 authentication errors
   - Handle 404 errors for invalid session IDs
   - Display user-friendly error messages for 422 validation errors
   - Implement retry logic for 500 server errors
   - Handle 401 errors for expired JWT tokens

4. RESPONSE PROCESSING:
   - The "answer" field contains the AI's response to the user's message
   - The "score" field contains the score for the current question (0-10)
   - The "remaining_questions" array shows what questions are left
   - The "all_scores" array contains scores for all completed questions
   - Final score is the average of all question scores

5. REPORT GENERATION:
   - The "latex_report" field contains an HTML-formatted transparency report
   - This is a complete HTML document with embedded CSS styling
   - The report can be directly saved as an HTML file or converted to PDF
   - The report includes detailed analysis of all responses and final scoring
   - Report uses Deep Blue color scheme and A4 paper size optimization

6. CONTEXT USAGE:
   - The "context" object in requests helps the AI provide more relevant responses
   - Include user_role, language, and platform information when available
   - This helps customize the assessment experience

NOTES
=====================================

- The API is currently in demo mode and accepts any username/password for login
- Assessment endpoints (/api/assessment/respond and /api/assessment/{session_id}/report) do NOT require authentication
- Other endpoints require JWT authentication (except login and health)
- JWT tokens expire after 30 minutes
- CORS is enabled for all origins

- Each response is scored 0-10 and contributes to the final assessment score
